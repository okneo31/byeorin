# 벼린 환율 (Byeorin Rates)

> **1 TTL = 노동자 1일 품삯. 국적과 무관하다.**
>
> 이 문서는 `packages/wallet-sdk/src/rates/` 와 `rate-snapshot.json` 이 무엇을
> 주장하고 무엇을 주장하지 않는지를 적는다. 스냅샷 기준: `v: 1` ·
> `anchoredAt: 2026-07-29` · 66종 산출 · 미해결 0종.

---

## 0. 이 환율이 주장하는 것 / 주장하지 않는 것

[VERIFIABILITY.md](./VERIFIABILITY.md) 와 같은 규칙을 쓴다 — 확인된 것과
확인하지 못한 것을 섞어 말하지 않는다.

| | |
|---|---|
| **주장한다** | 각 통화의 1일 1인당 명목 산출액을 공개 데이터로 계산했고, 그 계산이 재현 가능하다 |
| **주장하지 않는다** | 이 값이 시장환율이다 |
| **주장하지 않는다** | `t{ISO}` 토큰이 실제 그 나라 통화와 교환된다 |
| **주장하지 않는다** | 이 값이 실제 임금·구매력·생활비다 |
| **주장하지 않는다** | 이 값이 앞으로 갱신된다 |
| **주장하지 않는다** | TTL 자신의 값이 여기 있다 — 스냅샷은 `t{ISO}` 의 `perTtl` 만 담는다 |
| **주장하지 않는다** | 상장자산의 TTL 표시가 TTL 의 값을 정한다 — 그것은 측정이지 앵커가 아니다(§2.1) |
| **주장하지 않는다** | 이 문서에 적힌 숫자가 영구값이다 — 전부 `anchoredAt` 시점의 사본이고, 스냅샷을 다시 만들면 바뀐다(§2.2) |

### 시장환율이 아니다

시장은 "베트남의 하루가 미국의 하루보다 19배 싸다"고 말한다. 이 체계는 그
가격을 입력으로 쓰지 않는다. 산식 어디에도 환율이 들어가지 않는다 — GDP 는
자국통화 단위로 받고, 나누는 값은 인구와 365뿐이다.

결과적으로 두 체계의 숫자는 다르다. 예: 스냅샷 기준 `1 tUSD = 572.39 tKRW`.
이것은 원/달러 시장환율이 아니고, 그것을 근사하려는 값도 아니다.

### `t{ISO}` ≠ 실제 통화

`tUSD` 는 달러가 아니다. 실제 달러와 1:1 이 아니며, 상환·예치·페그 어느 것도
없다. ISO 코드를 쓰는 이유는 **어느 나라의 하루 산출을 기준으로 값이
정해졌는지** 를 가리키기 위해서다. 실제 통화와 섞어 읽으면 안 된다.

## 1. 산식

```
perTtl = 명목GDP(자국통화) / 인구 / 365

1 TTL = perTtl 단위의 t{ISO}
```

`365` 는 TTL 페그 계산(연 단위 ÷ 365)과 같은 나눗수다.
스냅샷의 `daysPerYear` 필드에 들어 있다.

| 데이터 | 출처 |
|---|---|
| 명목 GDP (자국통화) | World Bank `NY.GDP.MKTP.CN` (GDP, current LCU) |
| 인구 | World Bank `SP.POP.TOTL` |
| 토큰 목록 (심볼·주소·decimals) | `https://scan.ttl1.top/api/tokens?limit=500` |

연도는 2025 를 우선하고 없으면 2024 로 내려간다. **어느 연도를 썼는지는 항목마다
`inputs.gdpYear` / `inputs.populationYear` 에 기록된다.**

## 2. 두 앵커는 별개 트랙이다 — 앵커와 측정은 다른 개념이다

| | 앵커 1 | 앵커 2 |
|---|---|---|
| 대상 | TTL 의 **외부 시세** | 통화토큰의 **TTL 환율** |
| 입력 | BTC 63,412.45 @ 2026-07-29 00:00 KST | 2025 명목GDP / 인구 |
| 산출 | TTL 초기 시세 (이후 페깅 해제) | 66종 `perTtl` |
| 기록 위치 | 이 스냅샷에 **없다** | `rate-snapshot.json` |

둘은 만나지 않는다. 스냅샷의 `rates` 배열에는 BTC 도, 달러 시세도, TTL 의 외부
가격도 들어 있지 않다 (테스트 `BTC 앵커는 이 스냅샷 어디에도 등장하지 않는다`
가 이를 지킨다).

**"만나지 않는다"가 무엇에 대한 말인지 정확히 해 둔다.** 두 개의 다른 관계가
한 단어로 뭉쳐지면 §2.1 이 모순처럼 읽힌다.

| | 방향 | 이번 결정 |
|---|---|---|
| **앵커** | 무언가 → TTL 의 값 (TTL 로 **들어오는** 화살표) | 0 개. 바뀌지 않았다 |
| **측정** | TTL 이라는 단위 → 다른 자산의 표시 (TTL 에서 **나가는** 화살표) | 허용된다 (§2.1) |

"만나지 않는다"는 **앵커**에 대한 말이다. 나가는 화살표는 자의 눈금을 바꾸지
않으므로 이 문장을 깨지 않는다.

**왜 별개여야 하는가.** 두 통화토큰 사이의 교환비는 TTL 을 거쳐 계산되므로 TTL
의 절대 눈금이 약분된다:

```
crossRate(from, to) = to.perTtl / from.perTtl
```

TTL 이 외부에서 얼마로 평가되든 이 값은 변하지 않는다. 앵커 1 이 흔들려도 앵커 2
가 정하는 상대 관계는 그대로다.

### 2.1 다른 자산을 TTL 로 재기 (2026-08-04)

**TTL 이 기준이다. 모든 자산을 TTL 로 잰다.** 상장자산도 예외가 아니다.

```
그 자산의 TTL 값 = 시장 USD 시세 × (1 USD 당 TTL)
1 USD 당 TTL = 1 / rateByIso('USD').perTtl        ← 런타임 조회. 숫자를 적지 않는다
```

**이 문서는 계수의 값을 적지 않는다.** 적는 순간 그 숫자가 스냅샷과 두 벌이
되고, 재앵커되면 문서 쪽이 거짓이 된다. 값이 필요하면 스냅샷을 읽는다.
`rateByIso('USD')` 가 `null` 이면 계산하지 않고 **비운다** — 옛 값으로 떨어지지
않는다(§2.2).

**무엇이 유지되는가 — TTL 의 값은 어디서도 시장에서 오지 않는다.** `perTtl` 의
산식(§1)에 입력이 하나도 더해지지 않았다. 위 곱셈은 `perTtl` 을 **읽기만** 한다.

**왜 이것이 옛 페그가 아닌가.** 옛 페그(`TTL = 10/365 BTC`)는 TTL 잔액에 BTC
시세를 곱했다 — TTL 의 값이 시장을 따라갔다. 여기서는 곱셈이 반대 방향이다.
시장 시세는 **재어지는 자산의 성질**이지 **자(尺)의 성질**이 아니다. BTC 를 TTL
로 재도 `perTtl` 은 한 자리도 움직이지 않는다.

> **금지선 (a) — TTL 잔액에 어떤 시세도 곱하지 않는다.**
> 허용된 곱셈은 `상장자산 USD 시세 × USD당 TTL` 하나뿐이다. 좌변에 TTL 잔액이
> 오는 곱셈이 코드에 나타나면 그것이 위반이다. TTL 잔액에 허용된 연산은
> 자기 정의 표시(`tokens.value_labor_days`, 곱셈 0 회)뿐이다.
> 방향이 뒤집히면 옛 페그로 되돌아간다 — 이 문단을 근거로 되돌린다.
> 이것은 문장만이 아니라 타입으로도 막혀 있다: `AssetRef` 의 `'ttl'` 갈래에는
> `symbol` 필드가 없어 시세표에 넘길 것이 없고, `assetValueInTtl` 은 그 분기에서
> 즉시 반환한다 — 그 아래로 `ctx.prices` 가 한 번도 등장하지 않는다.

**고정 액면과 시세 기준은 구분된다.**

| 종류 | TTL 값의 출처 | 움직이는가 |
|---|---|---|
| TTL | 자기 정의 (노동자 N 일 품삯) | 환산하지 않는다 |
| `t{ISO}` | `rateByAddress` → `perTtl` | 아니오 (스냅샷 고정) |
| 스테이블 | 액면 ISO → `rateByIso` → `perTtl` | 아니오 (스냅샷 고정) |
| 상장자산 | 시장 USD 시세 × USD당 TTL | **예 (시세를 탄다)** |

마지막 행만 출렁인다. 화면에서 구분되지 않으면 그 출렁임이 "TTL 이 BTC 를
따라간다"로 읽혀 방금 지운 페그와 구별이 안 된다.

**값을 모르면 비운다.** 주소로 신원이 확인되지 않은 토큰은
`tokens.value_unverified`, 시세·액면을 못 얻은 토큰은 `tokens.value_unlisted`.
심볼 문자열로 판정하지 않는다 — 가짜 USDT 가 값을 얻는 구멍(v0.5.20 에서 막음)이
다시 열린다.

**포트폴리오 합계.** 모든 자산이 같은 자로 재어지므로 TTL 합계가 성립한다.
합계에 값 미상 자산이 섞이면 그 사실을 함께 표시한다. 빠진 것을 숨긴 합계는
거짓이다.

**산식은 한 곳.** `packages/wallet-sdk/src/rates/` 의 순수 함수
(`assetValueInTtl`)만 이 곱셈을 한다. 셸 4 종은 부른다. v0.5.21 에 셸마다 짜서
4 벌이 어긋났고 v0.5.22 를 통째로 그 수습에 썼다.

### 2.2 환율은 상수가 아니다 — 코드에 숫자로 박지 않는다

**금지선 (b).** `perTtl` 도, 그 역수도, 어떤 통화의 환산 계수도 소스에 리터럴로
쓰지 않는다.

**왜.** `perTtl` 은 `명목GDP(자국통화) ÷ 인구 ÷ 365` 이고 원천은 World Bank
API 다(§1). `node scripts/build-rate-snapshot.mjs` 를 다시 돌리면 66 종이 전부
새 값으로 바뀐다. 스냅샷에 `anchoredAt` 이 있는 이유가 그것이다 — 이 값들은
**어느 시점의 것**이지 영구값이 아니다. 코드에 박힌 숫자는 재앵커 순간부터
스냅샷과 다른 값이 되고, 그 순간 그것은 캐시가 아니라 **두 번째 앵커**다.

| 규칙 | 내용 |
|---|---|
| ① 런타임 조회 | 값은 스냅샷에서 읽는다. 하드코딩·기본값·폴백 상수 전부 금지 |
| ② 없으면 비운다 | 스냅샷을 못 읽거나 그 통화가 없으면 값을 비운다. 옛 값으로 떨어지면 조용히 틀린 금액이 뜬다 — 빈칸은 보이지만 틀린 숫자는 안 보인다 |
| ③ 앵커를 밝힌다 | 화면에 TTL 값을 보일 때 어느 앵커의 값인지(`anchoredAt`) 사용자가 확인할 수 있어야 한다 |
| ④ 테스트로 고정 | (i) 소스에 환율 숫자 리터럴이 없다 (ii) 스냅샷 값을 바꾸면 결과가 따라 바뀐다 — 두 가지를 테스트가 지킨다 |

**이 문서의 숫자도 같은 성질이다.** §6 의 값 표와 §5 의 검산 예시는 `anchoredAt`
시점의 사본이다. 코드가 참조할 대상이 아니라 사람이 눈으로 대조할 대상이다.

## 3. 왜 명목 GDP 인가

**실질 GDP 를 쓰지 않는 이유는 두 가지다.**

1. 실질 GDP 는 인플레이션을 제거한 지표다. 그런데 이 체계가 재려는 것 중
   하나가 바로 그 인플레이션이다. 실질을 쓰면 화폐를 얼마나 찍든 TTL 대비
   가치가 떨어지지 않는다 — 통화 남발이 환율에 반영되지 않는다.
2. 실질 GDP 는 기준연도(base year)가 나라마다 다르다. 한 나라는 2015년 가격,
   다른 나라는 2020년 가격으로 표시된 값을 나란히 놓으면 국가 간 비교가
   성립하지 않는다.

## 4. 왜 자국통화 단위인가

달러 환산 GDP(`NY.GDP.MKTP.CD`)는 **World Bank 가 이미 시장환율을 곱해 만든
값**이다. 그것을 입력으로 쓰면 배제하려던 시장환율이 뒷문으로 들어와,
산식에서 환율을 빼놓은 것이 무의미해진다.

`NY.GDP.MKTP.CN` 이 정확히 "current LCU" — 당해가격·자국통화다. 그래서 이 지표를
쓴다.

## 5. 재현 방법

스크립트를 저장소에 두는 이유는 제3자가 같은 입력으로 같은 값을 나오게 할 수
있어야 하기 때문이다. 숫자만 있고 절차가 없으면 믿으라는 말밖에 안 된다.

```sh
node scripts/build-rate-snapshot.mjs --out /tmp/repro.json
```

이 스크립트는 네트워크를 쓴다 (World Bank API + TTL Scan 토큰 목록).
산출물을 저장소의 것과 대조한다:

```sh
diff <(jq -S . rate-snapshot.json) <(jq -S . /tmp/repro.json)
```

`--out` 을 주지 않으면 저장소 루트의 `rate-snapshot.json` 을 덮어쓰므로, 검증
목적이라면 반드시 `--out` 으로 다른 경로를 지정한다.

### 스크립트는 파일 두 개를 함께 만든다

| 파일 | 용도 |
|---|---|
| `rate-snapshot.json` | 사람이 눈으로 검증하는 산출물 |
| `packages/wallet-sdk/src/rates/snapshot.ts` | 코드가 import 하는 사본 (생성물, 손대지 않는다) |

둘은 한 번의 실행에서 같이 나오므로 어긋날 수 없다. **단, `--out` 으로 다른
경로를 줘도 `snapshot.ts` 는 항상 제자리에 덮어쓴다** — 검증 실행이 SDK 소스를
바꾼다. 재현 검증 후 `git diff packages/wallet-sdk/src/rates/snapshot.ts` 로
확인하고, 변화가 없어야 정상이다.

### 항목 하나만 손으로 확인하기

각 rate 는 계산에 쓴 입력을 그대로 싣고 있다. 계산기 한 번이면 된다.

```json
{
  "symbol": "tKRW",
  "perTtl": 141180.04441511573,
  "inputs": {
    "gdpLocal": 2663342600000000,
    "gdpYear": "2025",
    "population": 51684564,
    "populationYear": "2025"
  }
}
```

```
2663342600000000 / 51684564 / 365 = 141180.04441511573
```

테스트 `perTtl 이 inputs 로 재계산된다` 가 66종 전부에 대해 이 등식을 확인한다
(부동소수점 오차 없이 `===` 일치).

## 7. API

`packages/wallet-sdk/src/rates/index.ts`. 스냅샷은 import 되는 상수라 네트워크
호출이 없다.

| 함수 | 반환 |
|---|---|
| `rateByAddress(address)` | `TokenRate \| null` — 대소문자 무관 |
| `rateByIso(iso)` | `TokenRate \| null` |
| `tokenAmountToTtl(baseUnits, decimals, rate)` | `number \| null` |
| `ttlToTokenAmount(ttl, rate)` | `number \| null` |
| `crossRate(from, to)` | `number \| null` |
| `authoritativeDecimals(address, fallback)` | `number` — 스냅샷 decimals 가 익스플로러 값을 이긴다 |
| `stableDenomOf(...)` / `stableFaceRate(denom)` | 스테이블의 **액면 통화** 판정 — 주소로만. 심볼 문자열은 쓰지 않는다 |
| `stableAmountToTtl(...)` / `stableToTtl(...)` | 액면 → `perTtl` → TTL |
| `tokenIdentityOf(id, family, chainId)` | `TokenIdentity` — 주소 신원. 미확인이면 시세를 **묻지 않는다** |
| `symbolUnitUsd(symbol, prices)` | 상장자산 1 단위의 USD. 시세표가 없으면 `null` |
| `assetValueInTtl(asset, ctx)` | `AssetValue` — 자산 종류를 가리지 않는 단일 환산 (§2.1). TTL 잔액을 시세로 곱하는 역방향 함수는 만들지 않는다 |
| `sumTtl(values)` | `TtlSum` — 합계와 **값 미상 개수**를 함께 낸다. 빠진 것을 숨긴 합계는 거짓이다 |
| `unresolvedRates()` | `readonly UnresolvedRate[]` |
| `snapshot()` | `RateSnapshot` — 산식·출처·입력값·`anchoredAt` 전체 |

**계수를 코드에 적지 않는다.** 위 함수들은 전부 스냅샷을 런타임에 읽는다. 호출부가
결과를 상수로 복사해 두면 §2.2 위반이다.

**주소로 찾는다.** 심볼로 찾지 않는 이유는 심볼이 겹치기 때문이다. `tUSD` 를
대문자화하면 `TUSD` 가 되고 이는 이더리움 메인넷의 TrueUSD 와 같다. 심볼 키
맵이었다면 TrueUSD 잔액에 벼린 환율이 붙는다. 테스트가 이 오작동을 재현해
못 박아 두었다 (`심볼 키 맵이었다면 TrueUSD 가 tUSD 환율에 잘못 걸린다`).

**환율을 모르면 `null` 이다. `0` 이 아니다.** `0` 을 돌려주면 화면에서 "가치
없음"으로 읽힌다. 모르는 것과 없는 것은 다르다.

**큰 수.** `perTtl` 이 34만을 넘고 `decimals` 가 18 인 조합(`tVND`)에서 base
unit 을 `Number()` 로 한 번에 변환하면 정밀도가 깨진다. 구현은 정수부와 소수부를
나눠 만든다. 정확히 1 TTL 어치를 넣었을 때 순진한 구현은 `1.0000000000000002`
를, 현재 구현은 `1` 을 낸다 — 테스트가 두 값을 모두 확인한다.

## 8. 한계 (숨기지 않는다)

| 항목 | 상태 |
|---|---|
| **스냅샷 이후 변동을 만드는 동력이 없다** | 이 값들은 한 번 계산되고 고정됐다. 갱신 주체·주기·트리거 어느 것도 정해져 있지 않다. GDP 나 인구가 바뀌어도 스냅샷은 그대로다. |
| **대만(`tTWD`)은 출처가 다르다** | World Bank 에 대만이 없어 IMF DataMapper 로 채웠다. IMF 도 자국통화 GDP 계열을 노출하지 않아 `PPPGDP × PPPEX` 항등식으로 자국통화 GDP 를 복원했다. 달러 환산 GDP(`NGDPD`)는 시장환율이 이미 곱해진 값이라 쓰지 않았다. 이 유도가 맞는지는 한국·일본·미국·독일에서 World Bank 자국통화 GDP 와 대조해 확인했다(오차 0.00~0.02%). `inputs.gdpSynthetic` 에 합성값임을 표시한다. |
| **미해결 통화는 현재 0 건** | 모든 통화가 값을 갖는다는 뜻이지, 모든 값이 같은 품질이라는 뜻은 아니다. 합성값(유로존·XOF·대만)은 `inputs.gdpSynthetic` 로 구분된다. |
| **`tAED` 만 2024 연도** | 나머지 65종은 GDP·인구 모두 2025. `tAED` 는 GDP·인구 둘 다 2024 다. |
| **유로존은 합성값** | World Bank 의 EMU 집계에 자국통화 GDP 가 없어, 회원국 20개국의 GDP 를 더했다(전부 EUR 표시). 인구는 EMU 집계를 그대로 썼다. `inputs.gdpSynthetic` 에 표시된다. 합산 대상 20개국 목록은 `scripts/build-rate-snapshot.mjs` 의 `EURO_AREA_MEMBERS` 에 있다. |
| **`tXOF` 는 코트디부아르 한 나라 값** | XOF(서아프리카 CFA franc)는 여러 나라가 함께 쓰는 통화지만, 토큰 목록이 이 통화를 코트디부아르 하나에 연결하고 있어 그 나라 GDP·인구만 들어갔다. 통화권 전체 합산이 아니다. |
| **1인당 산출 ≠ 임금** | `GDP / 인구 / 365` 는 1인당 하루 산출액이지 실제로 노동자가 받는 하루 임금이 아니다. 노동소득분배율, 비경제활동인구, 소득분포 어느 것도 반영되지 않는다. |
| **World Bank 데이터는 개정된다** | 산출 시점의 값을 박아 넣은 것이다. 나중에 스크립트를 다시 돌리면 API 쪽 값이 개정돼 다른 결과가 나올 수 있다. 그 경우 재현 실패가 아니라 원본 데이터가 바뀐 것이다. |
| **`anchoredAt` 은 날짜까지다** | `rate-snapshot.json` 은 `anchoredAt`(현재 `2026-07-29`)을 담는다 — 어느 앵커의 값인지는 이것으로 확인한다(§2.2 ③). 다만 시각(시·분)은 없어, 같은 날 두 번 생성한 스냅샷은 이 필드로 구별되지 않는다. |
| **토큰 목록은 TTL Scan 에 의존** | 어떤 `t{ISO}` 토큰이 존재하고 주소가 무엇인지는 `scan.ttl1.top` 응답에서 온다. 재현하려면 그 엔드포인트가 같은 목록을 돌려줘야 한다. |
| **decimals 는 전부 18** | 66종 모두 18. 다른 값이 섞이면 계산은 여전히 맞지만, 이 문서의 예시 수치는 18 기준이다. |
