## 2. D1 — 심볼로 값을 매기던 문제

### 무엇이 문제였나 (사실)

`tokenToUsd(symbol, prices)` 가 `symbol.toUpperCase()` 한 문자열을 `STABLE_USD = {USDT:1, USDC:1, DAI:1, BUSD:1, TUSD:1}` 표에서 찾아 `1` 을 돌려줬다. 심볼은 체인이 보장하지 않는 값이다 — **누구나 `symbol()` 이 `"USDT"` 를 반환하는 컨트랙트를 배포**할 수 있고, 그러면 그 토큰이 지갑 화면에 **개당 1 달러**로 찍혔다. 잔액이 100만이면 화면에는 100만 달러가 떴다.

v0.5.19 에서 TRON 토큰의 `symbol()` 을 실제로 읽어 이름표를 붙이기 시작하면서 **이 경로가 새로 열렸다.** 그 전에는 TRON 토큰이 주소 축약으로 표시돼 표에 걸리지 않았다.

TRC-20 은 **사용자 조작 0 회**로 성립했다: 공격자가 배포 → 피해자 주소로 전송 → TronGrid 계정 조회가 보유 목록을 자동 수신 → 심볼을 읽어 표시 → $1. SUI / APTOS / TON 도 발행자가 메타데이터 심볼을 정하므로 같은 구조였다. EVM 과 XRP 는 사용자의 선행 행동(토큰 수동 추가 / 트러스트라인 설정)이 있어야 목록에 올랐다.

피해 범위(코드로 확인한 한계): 값이 쓰이는 곳은 **화면 문자열 하나뿐**이다. 포트폴리오 합계·정렬·수수료·스왑 라우팅·송금 어디에도 이 값이 들어가지 않는다(스왑은 주소로 풀을 찾고 리저브로 계산한다). 즉 지갑이 만든 것은 **잔액 오인**이고, 손실은 사용자의 후속 행동을 거쳐야 발생한다. 여기까지가 사실이다.

코드는 이미 같은 함정을 절반 알고 있었다. `lookalike` 가드가 `/^t[A-Z]{3}$/` 로 `tUSD → TUSD` 만 막았고, 바로 위 주석은 "심볼은 판단에 쓰지 않는다" 라고 선언해 놓고 다음 줄에서 심볼을 썼다. **이번에 선언 쪽으로 맞췄다.**

### 이제 무엇으로 신원을 판정하나

키는 전부 **주소(또는 체인 고유 식별자)** 다. 네트워크를 타지 않고 앱 안 상수만 조회한다(조회 비용 상수).

| 순서 | 근거 | 키 | 위조 가능성 |
|---|---|---|---|
| 1 | 벼린 환율 스냅샷 `rateByAddress` | 0x 주소 | 없음 — 커밋된 앵커 |
| 2 | EVM 내장 목록(격리 `TokenRegistry` 인스턴스) | chainId + 0x 주소 | 없음 — 하드코딩, 체인 교차 불가 |
| 3 | TRC-20 내장 목록 `TRUSTED_TRC20` | base58 정본(정규화 없음) | 없음 |
| — | 그 외 전부 | — | **미확인 → 값 비움** |

세 가지에 걸리지 않으면 `tokenToUsd` 를 **호출조차 하지 않는다.** 심볼은 표시에만 쓴다.

핵심 격리: `const BUILTIN_TOKENS = new TokenRegistry()` — 새 인스턴스는 생성자가 하드코딩 BUILTIN 만 복사하고, 이 인스턴스에는 `addCustomToken` 이 한 번도 불리지 않는다. 공용 레지스트리를 봤다면 ttlscan 탐색분·사용자 수동추가분이 섞여 게이트가 무의미해졌을 것이다.

미확인 토큰은 값 칸을 그냥 비우지 않는다 — 빈칸은 "0" 으로 읽히기 때문이다. 잔액 > 0 이면 숫자 자리에 문장을 넣는다: **"값 모름 · 신원 미확인"**, 툴팁에 이유("컨트랙트 주소가 지갑의 확인 목록에 없습니다. 심볼은 누구나 똑같이 지을 수 있어 값 판단에 쓰지 않습니다").

### 값이 사라지는 토큰 — 사용자가 보던 숫자가 없어진다

**유지되는 것**
- TTL 체인 토큰 66 종 → 벼린 환율 → TTL 환산 그대로.
- EVM 8 체인 내장 토큰(USDC·USDT·DAI·WETH 가 ethereum/polygon/arbitrum/optimism/base/bsc/avalanche 전부에 들어 있다) → **실사용 EVM 스테이블 값은 사라지지 않는다.**
- TRON USDT(`TR7NHq…Lj6t`) → $1 유지.
- ZION 패널 4 종(denom 하드코딩) → 유지.
- 상장자산 native USD 보조줄 → 손대지 않음.

**사라지는 것 (의도된 회귀)**
1. **Solana SPL 전부** — 저장소에 mint 허용목록이 없다. **진짜 USDC(`EPjFWdd5…`)·USDT 도 값이 사라진다.**
2. **TRON USDT 이외 TRC-20 전부** — v0.5.19 에서 열린 경로가 다시 닫힌다.
3. **TON Jetton / Aptos Coin·FA / Sui Coin / XRP issued currency 전부** — 허용목록 없음. 진짜 스테이블 포함.
4. **EVM 사용자 수동 추가 토큰 전부** — 주소가 내장 목록과 같으면 유지.
5. **ttlscan 탐색 TTL 체인 토큰 중 환율 스냅샷에 없는 것.**

되살리는 유일한 길은 심볼을 다시 믿는 것이 아니라 **주소 허용목록에 근거(evidence)를 달아 추가**하는 것이다(`trc20-known.ts` 의 절차 복제).

`lookalike` 가드는 새 규칙에 **완전히 흡수돼 삭제**했다 — 심볼 정규식 자체가 규칙 위반이었고, `USDT` 직접 사칭은 못 막는 부분해였다.

## 3. D2 — TTL 을 달러로 환산하던 잔재

남아 있던 **2 곳**:

| 셸 | 위치 | 있던 표시 |
|---|---|---|
| web | `apps/web/src/screens/Account.tsx` 잔액 히어로 | `≈ $… USD` (값 없으면 `≈ — · 시세 없음`) |
| desktop | `apps/desktop/src/views/Wallet.tsx` 잔액 카드 | `≈ $… USD` |

왜 위반인가: `docs/CONTEXT.md` §5 는 BTC 페깅 해제 / 벼린 환율의 기준은 TTL / 두 앵커는 만나지 않는다 로 닫혀 있다. **TTL 은 TTL 이다. 가치가 그 자체다** — 원화스테이블·달러스테이블이 TTL 을 기준으로 재어지는 것이지 그 반대가 아니다. 게다가 값의 출처가 CoinGecko 라이브 조회(`ids=ttl`)였고, 그 id 가 우리 체인의 TTL 이라는 보장이 코드 어디에도 없다 — 페그 위반이면서 동시에 "모르는 값을 아는 척" 경로였다.

지금 표시되는 것: **`노동자 {v} 일 품삯`** (en: `{v} days of a worker's wage`). 1 TTL = 노동자 하루 품삯이므로 **환산 계수가 없다 — 잔액 숫자가 곧 일수다**(곱셈 0 회). 4 종 셸이 같은 i18n 키 `tokens.value_labor_days` 를 쓴다(android / extension / desktop / web 각 1 곳, 실측 4/4 일치).

제거 후 web·desktop 에서 CoinGecko 호출은 **0 회**가 됐다. TTL 과 상장자산을 한 숫자로 더하는 합계 코드는 **0 건**(원래도 없었다).

## 7. 남은 것

**(가) 사용자가 수동 추가한 가짜 토큰은 값이 붙는가 — 붙지 않는다.**
게이트는 격리된 내장 목록만 본다. 사용자가 스캠 주소를 붙여넣어도 그 주소는 내장 목록에 없으므로 `null` → "값 모름 · 신원 미확인". 심볼과 이름은 여전히 컨트랙트가 말한 대로 표시된다(**표시는 막지 않는다 — 값만 막는다**). 즉 화면에 "USDT" 라는 글자는 뜰 수 있고, 그 옆에 달러 숫자는 안 뜬다.

**(나) 사유 문구가 한 경우에 틀린다 — 이번 라운드에 안 고쳤다.**
신원이 **확인된** 토큰인데 시세가 없으면(시세 조회 실패로 `prices===null`, 또는 `USDC.e`·`WETH.e`·`WBTC.e` 처럼 거래 페어가 없는 내장 항목) 값 슬롯에 "값 모름 · **신원 미확인**" 이 뜬다. 신원은 확인됐다. 사실이 아닌 사유를 화면에 적는 것이고, 이는 이번 결함군의 공통 원인의 거울상이다. 정확히 이 경우를 위한 키 `tokens.value_unlisted`("시세 없음")를 i18n 에 만들어 뒀으나 **코드 참조 0 건**이다. 수정 방향은 확정돼 있다: `신원 있음 && 값 없음 → value_unlisted`, `신원 없음 → value_unverified`. 시세 조회가 통째로 실패하는 순간 정상 EVM 스테이블 전부가 "신원 미확인" 으로 보이므로 빈도는 낮지 않다.

**(다) CSS 미적용.** `zion-assets__usd--unknown` 클래스가 android·extension 스타일시트 어디에도 정의돼 있지 않다(클래스 이름은 코드 2 곳에 붙어 있다). 미확인 문구가 정상 값과 같은 색·크기로 렌더된다. 오독 방지는 문장 자체가 하므로 기능 결함은 아니고, 의도(흐린 회색)만 미달이다.

**(라) 상장자산 native USD 보조줄 — 이번에 건드리지 않았다. 사람이 정할 사안.**
BTC·ETH·SOL·TRX·TON·APT·SUI·XRP 의 native 잔액 아래 USD 보조줄은 그대로다. 수량+심볼이 메인이고 USD 는 별도 줄이라 치환이 아니며, §5 가 외부 상장자산의 Binance 표시를 명시 허용한다. 닫힌 결정 위반이 아니라 취향 차이다.

**(마) `sym.startsWith('W')` 재귀가 남아 있다.** 게이트가 위조 경로는 닫았지만(위 실증 9번), "심볼 첫 글자가 W 면 원본 자산과 1:1" 은 여전히 심볼 기반 산식이다. 완전 제거는 내장 항목에 가격키(`priceSymbol`/`usdPeg`)를 명시하는 변경과 세트다 — **작업량 = 38 줄 편집(8 체인 × 4~6 종) + `tokenToUsd` 서명 1 곳 + 셸 호출부 2 곳 = 41 개 편집 지점.** 이 결정은 사람이 한다.

**(바) 실기기 미검증.** 판정은 전부 코드 경로와 dist 실행으로 확정했다. 위조 토큰을 실제로 배포해 실기기 화면을 본 것이 아니다. 미확인 토큰 행의 레이아웃 변화(값 슬롯 내용이 바뀌면서 행 높이가 달라질 수 있음)도 실기기에서 확인하지 않았다.

**(사) 커밋되지 않았다.** 위 산출물은 미커밋 트리에서 나왔다. 커밋·푸시는 지시받지 않아 하지 않았다.
