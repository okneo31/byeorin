## 0. 확정된 원칙 (재논의 X — 2026-07-29 사용자 결정)

1. **가격은 풀의 수급이 정한다.** 벼린 환율(GDP/인구 스냅샷)은 방어할 페그가
   아니라 **창세 가격** — 풀을 처음 채울 때 한 번 쓰고, 그 뒤는 시장이 움직인다.
   BTC 앵커를 한 번 쓰고 해제한 것과 같은 패턴이다.
2. **노동가치는 환율이 아니라 TTL 그 자체다.** "1 TTL = 노동자 하루 품삯" 은
   단위의 정체성이지 지켜야 할 교환비가 아니다. 모든 가격이 TTL 로 표시되는
   것으로 원칙은 관철된다 — 시장이 tUSD/TTL 을 어디로 움직이든, 그 가격을
   읽는 자(單位)는 노동일이다.
3. **비수탁.** 자산은 컨트랙트에 들어가지 운영자에게 가지 않는다. 열쇠는 끝까지
   사용자 것이다 (CONTEXT §5 닫힌 결정과 정합).
4. **수수료 33bps.** 교차(2홉) 실효 ~0.66%.
5. **시딩: 풀당 TTL 1,440,000,000 고정.** 토큰 쪽 = perTtl × 1.44e9. 발행량
   (M2/10)을 넘는 41 종은 **추가 발행으로 채운다** — 공표된 M2/10 기준을 넘는
   발행임을 인지한 발행자 결정이다. 수치는 `genesis-seed.json` (생성기:
   `scripts/build-genesis-seed.mjs`, 입력은 커밋된 rate-snapshot 하나).
   TTL 총 95,040,000,000 개 (max 777.7B 의 ~12.2%).
6. **관리자 키는 발행자가 보유.** 권한은 V2 표준 feeTo/feeToSetter 뿐 — 준비금·
   LP 인출은 어떤 권한으로도 막을 수 없다(테스트 불변식). `setFeeToSetter(0)`
   이 일방향 포기 경로다. publisher 단일 키와 같은 방식으로 약점을 명시한다.

## 1. 왜 고정환율 교환소가 아닌가 (기각 근거)

고정가로 무제한 교환을 약속하면 그 가격이 시장과 어긋난 순간 무위험
차익거래가 열리고, 준비금이 유한한 이상 반드시 소진된다. 중앙은행이
고정환율을 방어하다 외환보유고를 잃는 구조와 동일하다. 벼린 환율을 거래
가격으로 쓰는 안은 이 이유로 기각됐다 — 환율은 **표시와 창세**에만 쓴다.

## 2. 왜 오더북이 아닌가 (사실 기반)

| | 오더북 | AMM |
|---|---|---|
| 저유동성 페어 | 호가가 비면 거래 자체가 불성립 | 유동성만 있으면 항상 체결 |
| 66 페어 유지비 | 페어마다 마켓메이커 필요 | 시딩 1회 |
| 수탁 | 매칭 엔진이 주문·자산을 쥐기 쉽다 | 온체인, 비수탁 |
| 검증 가능성 | 오프체인 매칭은 감사 불가 | 전 상태가 체인에 |
| 생태계 선례 | 없음 | **ZION AMM 이 이미 가동 중** (풀 3개, 실측) |

66개 통화토큰은 당분간 전부 저유동성이다. 오더북은 그 조건에서 성립하지
않는다. AMM(x·y=k)으로 시작한다. 오더북이 필요해지는 시점(고유동성 페어
등장)에 그 페어만 얹으면 된다 — 지금 결정을 막지 않는다.

## 3. 어디에 — TTL 체인 (EVM)

- 66종 통화토큰은 **TTL 체인(chainId 7777)의 ERC-20** 이다 (실측: tUSD
  컨트랙트 코드 존재). 거래소는 자산이 있는 곳에 있어야 한다.
- TTL 체인은 geth 1.13.15 포크로 EVM 컨트랙트 배포가 된다 — 66종 자체가 증거다.
- **ZION AMM 은 그대로 둔다.** ZION denom(utrg/ubtc/uusdt/ueth)의 교환은
  이미 그쪽에서 돌고 있고, 체인이 다르다. 두 거래소는 별개 트랙이다.
  (둘을 잇는 것은 브릿지 문제 — 본 설계 범위 밖.)

## 4. 풀 구조 — TTL 허브

```
모든 풀 = TTL / t{XXX}   (66개 페어)

tUSD → tJPY 교환 = 라우터가 한 트랜잭션에 2홉:
  tUSD → TTL → tJPY
```

**TTL 을 기축으로 강제하는 이유:**
- 유동성이 66개 페어에만 모인다. 임의 페어(tUSD/tJPY 직접 풀)를 허용하면
  유동성이 66×65/2 = 2,145 갈래로 쪼개져 전부 얕아진다.
- 모든 가격이 자연스럽게 TTL 표시가 된다 — 원칙 2 가 구조로 보장된다.
- 교차 환율은 두 풀에서 유도된다. 벼린 환율의 `crossRate` 와 같은 수학이다.

## 5. 창세 가격과 시딩

풀 페어(TTL, tXXX)의 초기 준비금 비율이 곧 초기 가격이다:

```
reserve_tXXX / reserve_TTL = perTtl        (rate-snapshot.json 의 값)

예) TTL/tUSD 풀에 TTL 1,000 개를 넣으면
    tUSD 는 1,000 × 246.65 = 246,650 개
    → 초기 가격 정확히 1 TTL = 246.65 tUSD
```

- 시딩 수치는 `rate-snapshot.json` 에서 기계적으로 유도되므로 **제3자가 창세
  가격이 조작되지 않았음을 재현 검증할 수 있다** (VERIFIABILITY 원칙).
- 시딩 직후가 가장 취약하다: 유동성이 얕을 때 소액으로 가격을 크게 움직일 수
  있다. 대응은 §8.
- 발행자가 66개 풀의 양변을 모두 댈 수 있다 (t 토큰 발행권 + TTL 트레저리).
  깊이는 §0-5 확정 — 풀당 TTL 1.44e9, 부족 토큰은 추가 발행.

## 6. 컨트랙트 — 최소·불변

Uniswap V2 계열 상수곱 3종만:

| 컨트랙트 | 책임 |
|---|---|
| `Factory` | TTL/tXXX 페어 생성. **TTL 이 아닌 쌍은 거절** (허브 강제) |
| `Pair` | x·y=k 준비금·스왑·LP 토큰. 검증된 수학 그대로 |
| `Router` | 다홉 경로, 슬리피지 보호, 기한(deadline) |

**검증 가능한 보안 원칙 적용:**
- **업그레이드 불가.** 관리자 권한은 feeTo/feeToSetter 뿐(§0-6). 규칙을 바꿀 수 있는
  키가 있으면 그 키가 곧 중앙 권위다. 수수료·수학은 배포 시점에 고정하고,
  바꾸려면 새 컨트랙트를 배포해 유동성이 스스로 이주하게 한다.
- 소스 공개 + 재현 빌드 + 배포 주소를 릴리스 앵커와 같은 방식으로 온체인 앵커.
- V2 수학을 변형 없이 쓴다 — 검증된 코드에서 멀어질수록 감사 비용만 늘어난다.

## 7. 지갑 통합

이미 있는 것을 재사용한다:

| 있는 것 | 재사용 |
|---|---|
| `ZionAmmClient` (listPools/quote/슬리피지) | 같은 형태의 `TtlAmmClient` — 견적 수학 동일 |
| `SwapPane` (ZION 스왑 화면) | 체인 무관 스왑 화면으로 일반화 |
| `TransferIntent.data` (EVM 계약 호출) | Router 호출도 같은 서명·브로드캐스트 경로 |
| 벼린 환율 `perTtl` | 스왑 화면에 "창세 가격 대비 현재가" 참고 표시 가능 |

## 8. 위험 — 숨기지 않고 적는다

| 위험 | 내용 | 대응 |
|---|---|---|
| 초기 저유동성 조작 | 얕은 풀은 소액으로 가격이 크게 움직인다 | 시딩 깊이 확보 + 지갑 기본 슬리피지 보호(0.5%) + 견적-체결 괴리 경고 |
| 시딩 스나이핑 | 창세 직후 봇이 불균형을 먹는다 | 창세 가격이 스냅샷과 일치하면 먹을 불균형이 없다 — 시딩 수치의 정확성이 곧 방어 |
| 2홉 수수료 | 교차 교환은 수수료 2배 | 33bps 로 낮게 확정 — 실효 ~0.66% (§0-4) |
| 무상장 가격 표류 | 시장가가 노동 기준에서 멀어질 수 있다 | **의도된 동작.** 원칙 1. 지갑이 창세 가격 대비 괴리를 표시해 정보만 제공 |
| LP 무상 손실 | 표준 AMM 리스크 | LP 문서에 명시. 초기 LP 는 발행자이므로 자기 위험 |
| 유동성 낭비 | 66 풀 중 수요 없는 페어 | 66 풀 동시 시딩 확정(§0-5) — LP 는 발행자라 자기 위험 |

## 9. 구축 단계

```
E-1  컨트랙트    Factory/Pair/Router + 테스트 (V2 수학 검증 벡터 포함)
E-2  창세 도구   rate-snapshot → 시딩 수치 생성기 (재현 검증 가능하게 저장소에)
E-3  배포        TTL 체인 배포 + 소스 공개 + 배포 앵커
E-4  SDK         TtlAmmClient (listPools/quote/buildSwap)
E-5  지갑        스왑 화면 일반화 (확장 + 안드로이드)
E-6  실측        소액 실스왑 → 문제 수정 → 시딩 본격화
```

E-1·E-2·E-4·E-5 는 병렬 가능. E-3 은 배포 키가 필요하므로 사용자 실행.
